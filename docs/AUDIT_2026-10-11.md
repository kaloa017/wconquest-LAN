Work is isolated from the running server and its database. Baseline: 146 Python
tests, client audit, JavaScript syntax, dependency and release checks passed.

Verified findings recorded before implementation:

Additional production review found that app.py:1551 discards fractional barracks
recruitment at every collection, and app.py:1772 retains schema-18 queues during
an explicit round reset. Schema 19 persists recruitment fractions; explicit
player/round resets clear the corresponding queues. No automatic reset is added.

Validation uses disposable Flask databases and browser request interception. No
claim is made about a penetration test, live tunnel availability or host capacity.

## Completed validation

- 159 Python tests pass, including 13 new regressions for account isolation,
  attempt protection, production boundaries, reset queues, fractional recruitment,
  transactional rollback and a backed-up schema-18 upgrade.
- 18 experience and 14 progression browser checks pass using intercepted requests,
  including 320, 390, 768 and 1440 pixel layouts, keyboard navigation and deliberately
  delayed responses. No browser page errors; mobile screenshots were inspected.
- All static JavaScript syntax checks, the client regression audit, public release
  validation and Git whitespace checks pass. The baseline dependency check passed;
  no dependencies changed.

Code/static files are version 6.6.2. The live server and save were not accessed or
restarted. The migration runs with a consistent SQLite backup on the host's next
normal startup. The existing inline-handler CSP allowance remains; removing it
needs a separate event-handler conversion. This was a targeted security and game
accounting audit, not a claim that every possible defect has been eliminated.
